# STE-UA: правила тексту

STE-UA — це українська версія ASD-STE100 Simplified Technical English.
Ці правила діють для службових текстів проєкту: файли `.md` і `.html`, документація дизайн-системи, хаб уроків, коміти, відповіді в чаті.

**Виняток — тексти інтерфейсу.** Кнопки, підписи, стани, повідомлення на екранах `wireframes/*.html` і рядки в `microcopy.md` пише tone of voice (`voice.md`, `microcopy.md`). STE-UA їх не переписує. Якщо такий рядок стоїть у службовому тексті, візьміть його в «…».

## Слова

- Одне слово — одне значення. Назвали річ один раз — далі називайте її так само.
- Беріть назви з реєстрів проєкту: екрани (`wireframes/_screens.md`), персони (`personas.md`), компоненти (`ui/inventory.md`), токени (`tokens.css`).
- Пишіть просте поширене слово, а не книжне. Пишіть «робити», а не канцелярит.
- Терміни домену (кімната, оголошення, анкета, співмешканець, станція метро, верифікація) і дизайну (токен, компонент, патерн, breakpoint) — дозволені.
- Не пишіть «тощо» і «і т. д.». Назвіть усі пункти або напишіть «наприклад».

Заборонені слова і заміни перевіряє лінтер. Список — `BANNED` у `tools/ste/check.py`.

| Заборонено | Пишіть |
|---|---|
| `здійснювати` | робити, вносити, платити |
| `являється`, `являє собою` | є |
| `даний` | цей |
| `наразі`, `на даний момент` | зараз |
| `у зв'язку з` | тому що, через |
| `з метою`, `задля` | щоб |
| `шляхом` | через |
| `в рамках` | у, під час |
| `необхідно` | треба |
| `забезпечувати` | давати, робити |
| `фактично`, `по суті`, `загалом` | приберіть |

## Без фразеологізмів і метафор

- Пишіть буквально. Фразеологізм, метафору й образ замініть прямим описом.
- Приклад. Не пишіть «кількість відгуків — нижня межа, знаменника немає».
  Пишіть «Людей з цією проблемою щонайменше стільки, скільки відгуків. Загальну кількість людей ми не знаємо».
- Лінтер блокує поширені образи: список — у `BANNED`, розділ «Фразеологізми».

| Образ | Пишіть |
|---|---|
| `біль`, `болі` | проблема |
| `тупик` | без виходу |
| `сирота` (екран, job) | екран без job, job без екрана |
| `щасливий шлях` | основний шлях |
| `голос людей` | слова людей, відгуки |
| `нижня межа` | щонайменше |
| `знаменник` | загальна кількість |
| `за раз` | за одну сесію, одразу |

## Речення

- Одне речення — одна думка.
- Інструкція — не більше 20 слів. Опис — не більше 25 слів. Лінтер блокує речення понад 25 слів.
- Пишіть активний стан: хто робить що. Пишіть «Гейт перевіряє файл», а не «файл перевіряється гейтом».
- Безособова форма на `-но`, `-то` дозволена для статусу: «Файл перевірено».
- Не пишіть дієприслівник (`-учи`, `-ючи`, `-вши`). Зробіть з нього окреме речення.
- Інструкцію починайте з дієслова: «Запустіть гейт».
- Одна дія — одна інструкція. Кілька дій — нумерований список.
- Умову ставте на початок: «Якщо гейт червоний, додайте токен у систему».

## Абзаци

- Абзац — одна тема. Не більше 6 речень.
- Перше речення каже головне.
- Кроки, варіанти й переліки — списком, а не абзацом.

## Що лінтер не перевіряє

- Код, URL, заголовки, таблиці-роздільники.
- Цитати: текст у «…», рядки `>` і `<blockquote>`. Цитати ресерчу лишайте дослівно.
- Довгий дослівний фрагмент без лапок — обгорніть у `<!-- ste-off -->` і `<!-- ste-on -->`.

## Гейт

- `python3 tools/ste/check.py --all` — перевірити весь репо.
- `python3 tools/ste/check.py FILE` — перевірити файли.
- Git `pre-commit` блокує коміт, якщо staged `.md` або `.html` має помилки.
- Хук Claude Code `PostToolUse` перевіряє файл після кожного `Edit` або `Write`.
- Хук Claude Code `Stop` перевіряє відповідь у чаті. Якщо є помилки, Claude переписує відповідь.
