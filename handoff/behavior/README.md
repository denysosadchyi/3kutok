# Специфікація поведінки

Специфікація описує поведінку п'яти флоу MVP. Вигляд, стилі й тексти в ній не повторено. Специфікація посилається на джерело, яке тримає цю річ.

## Головне правило: посилання, а не копія

Копія застаріє. Посилання лишається правдивим. Тому:

- **Компонент** — назва класу й стан. Приклад: «кнопка: `button--primary`, стан `disabled`, поки форма невалідна». Стилі — у `design-system/components/`.
- **Текст** — ключ рядка з [`microcopy.md`](../../microcopy.md). Приклад: «текст: `microcopy.md` → LS-31». Якщо ключа немає, специфікація посилається на шаблон з [`voice.md`](../../voice.md) → «Словник». Приклад: E1.
- **Крок флоу** — діаграма і вузол з [`flows.md`](../../flows.md). Приклад: «`flows.md` → Related 1, вузол `ER`».
- **Екран** — згенерований файл `wireframes/<назва>.html`. Розмітку тримає виклик `page("<назва>")` у `wireframes/_build.py`. Номерів рядків немає: вони застаріють.
- **Брак у системі** — ключ з [`design-system/backlog.md`](../../design-system/backlog.md). Приклад: «невалідного стану поля немає — B4».

## Мітки

- **код** — правило вже є в коді. Поруч стоїть посилання на функцію чи файл.
- **спека** — нове правило цієї специфікації. У статиці його немає. Якщо правило суперечить продукту, змініть його тут.
- **[?] Qn** — рішення немає ні в коді, ні в джерелах. Питання — у [`open-questions.md`](open-questions.md) під номером Qn.

## Спільні правила станів

Ці правила діють у кожному флоу. Файли флоу їх не повторюють. Визначення станів — `flows.md` → «Межі, ролі й позначення».

### Завантаження (`loading`)

- Стан з'являється, коли клієнт надіслав запит і ще не має відповіді.
- На місці вмісту стоїть скелетон тієї самої форми: компонент `skeleton` з модифікатором (`skeleton--line`, `skeleton--avatar`).
- Скелетон має `aria-hidden="true"`. Контейнер має `aria-busy="true"`.
- Читач екрана чує один рядок `sr-only` з `role="status"`. Текст — за шаблоном `voice.md` → Словник, E2.
- Дії, яким потрібні дані, ще недоступні. Приклад: на місці панелі дії стоїть `skeleton--button`.
- Глобальна навігація (`tabbar`) і кнопка «назад» працюють. Людина може піти до кінця запиту. Код: `flows.md` → «Глобальна навігація доступна також під час loading/error».
- Затримка показу скелетона й тайм-аут запиту — **[?] Q1**.

### Помилка (`error`)

- Стан з'являється, коли запит упав або минув тайм-аут (**[?] Q1**).
- Помилка — тільки технічний збій. Відмова людини, зняте оголошення й відсутність відповіді — не помилка. Код: `flows.md` → «Негативний результат щодо кандидата не є технічним `error`».
- Компонент: `state state--error` з `role="alert"`.
- Текст: шаблон `voice.md` → Словник, E1 («що сталося»). Дія повтору — Словник, D6.
- Повтор робить той самий запит з тими самими параметрами.
- Повтор — лише за явною дією людини. Автоматичного повтору немає (**спека**).
- Те, що людина ввела, не зникає: критерії, чернетка, поля форми.
- Якщо результат операції невідомий, клієнт спершу питає статус. Лише потім він повторює запит. Так не з'являється дубль. Код: `flows.md` → «Спільне відновлення».

### Порожній стан (`empty`)

- Стан з'являється лише після успішної відповіді без даних.
- Збій ніколи не показується як порожній стан.
- Компонент: `state` без `--error`. Якщо порожній лише розділ, а не екран, — блок `state-note`. Це разовий блок з `wireframes/screens.css`, не компонент системи.
- Порожній стан завжди має вихід: дію або навігацію. Екран без виходу — дефект.

### Успіх

- Успіх — відповідь з даними, яких досить для дії на екрані.
- Успіх екрана не дорівнює успіху job. Код: `wireframes/_screens.md` → «Спільний job головного шляху».

### Очікування людини

- Очікування відповіді іншої людини — не `loading`. Спінера немає.
- Код: `flows.md` → «Очікування людини показуємо без нескінченного spinner».

## Спільні правила форм

- Поле без значення не є помилкою, поки людина не спробувала відправити форму (**спека**).
- Помилку поля показуємо після втрати фокусу або після спроби відправки (**спека**).
- Невалідного стану поля, підказки й тексту помилки в системі немає — B4. Поки B4 не закрито, розробник не малює свій стан.
- Головна кнопка форми: `button--primary`, стан `disabled`, поки форма невалідна (**спека**).
- Стану кнопки «виконується» в системі немає — B7. Помилки операції без втрати форми немає — B8.
- Під час відправки кнопка не приймає повторного натискання (**спека**). Так не з'являється дубль.

## Розклад за шириною

Поведінка однакова на всіх ширинах. Ширина міняє лише розкладку: компонент `split`, точки `--bp-tablet` і `--bp-desktop`. Рішення — [`responsive/width-audit.md`](../../responsive/width-audit.md). Статус цього файла — **[?] Q2**.
