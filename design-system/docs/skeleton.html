3. Коли вживати

Скелетон стоїть на чотирьох екранах завантаження — listings-loading, listing-loading, profile-loading, chat-loading — і повторює форму того, що прийде: фото 4:3, рядки, аватар, бульбашки. Екран не смикається, коли дані з’являються.

Блоки приховані від читача екрана (aria-hidden); натомість поруч один role="status" зі словника: «Завантажуємо {оголошення / профіль / повідомлення}». Іконки в завантаженні немає — це свідоме рішення дизайнера.

Джерела: DESIGN.md → Components → Стани, Правки уроку 7 (скелетон у списку, скелетон людини); microcopy.md → Звірка після переписування → Статус завантаження; ui/inventory.md → Зворотний зв’язок

4. Правило і антиправило

5. Стани

Компонент не інтерактивний — наведення, натискання й фокусу не має. Завантаження показано у варіантах (скелет), вимкненого стану немає.

Правила для всіх компонентів такі. Наведення й натискання міняють лише фон, колір або рамку. Фон кнопки, чипа, «Надіслати», шапки й капсули меню проступає шаром за --dur-fast (розділ «Рух»). Фокус з клавіатури — кільце --color-focus (AA в обох темах).

Вимкнене — --opacity-disabled і без курсора. Кнопку й поле вимикає атрибут disabled (поза Tab). Вимкнене посилання — без href з aria-disabled="true".

6. Рух

Рух живе в компоненті, а не на екрані: що тут, те й на кожному екрані. Анімуються лише transform і opacity, лише через ролі --dur-* / --ease-* / --move-*; фокус і колір — миттєво. З prefers-reduced-motion: reduce рух вимкнено, кінцевий стан той самий.
