# План доробки уроку 2

Статус: реалізовано; зауваження finish review Fable та Astra опрацьовано
2026-09-11.

## 1. Доказовий каркас

- Замінити raw `.md#L…` посилання на читабельні HTML-секції та скріншоти.
- Біля кожного висновку показувати статус: факт про ринок, гіпотеза потреби,
  невідома важливість або невідомий ефект рішення.
- Не використовувати наявність функції конкурента як доказ поведінки людини.

Критерій: усі посилання відкривають реальний документ або зображення; жодного
неіснуючого fragment target.

## 2. Ланцюг persona → job → рішення

- Залишити Марту робочою primary `[?]`, Андрія secondary.
- Понизити Олену до scenario candidate: локальний попит на buddy-up не доведено.
- Повернути кожній ролі jobs довіри, сумісності, домовленості та контролю там,
  де їхня релевантність є гіпотезою.
- Додати повні «Коли / хочу / щоб» формулювання та стабільні ID без значення
  пріоритету.

Критерій: кожен продуктовий кандидат простежується до job і персони; функції
не заховані всередині формулювання job.

## 3. Продуктова ієрархія

- Розділити table stakes, differentiator hypotheses, safety requirement і
  not-yet-justified bets.
- Узгодити урок із core loop `пошук → профіль → прямий контакт`.
- Повернути пояснення вибору primary та функції-кандидати на виліт.

Критерій: «ядро» уроку 2 не суперечить `CLAUDE.md`.

## 4. Матриця

- Відмовитися від фальшивої шкали 1–3 до появи user research.
- Замість повторюваних `[?]` показати релевантність сценарію та окремий тип
  невідомого.
- Додати `scope="col"`, `scope="row"` і стабільні job IDs.
- На mobile перетворити ті самі table rows у вертикальні job-cards через CSS,
  без дублювання даних.

Критерій: матриця читається на 390 px без горизонтального скролу й зберігає
всі підписи колонок.

## 5. Навчальний і навігаційний шар

- Додати результат уроку, коротку методику proto-persona/JTBD і пояснення
  evidence labels.
- Додати mobile-зміст поточного уроку.
- Завершити блоком «Що перевіряємо далі» з трьома питаннями та рішеннями, які
  змінить відповідь.
- Підняти допоміжний текст джерел до читабельного розміру.

Критерій: логіка уроку зрозуміла без відкриття Markdown-файлів.

## 6. Перевірка

- Desktop: 1440, 1100, 1024 px; mobile: 390 px.
- Keyboard focus, disclosure labels, 200% zoom, JS fallback, console.
- Один detector pass після завершення UI.
- Один незалежний finish review і не більше одного пакета виправлень.

Фінальний критерій: читач може пройти від ситуації людини через job і доказ до
кандидата в продукт та побачити, яке саме невідоме блокує рішення.
